# R1 — Character data sources + licenses (research)
Status: todo · Suggested agent: fresh Claude Code (needs WebSearch/WebFetch) · Size: M · Device check: user (none needed)

## Goal
Pick the data sources the character feature ([architecture/characters.md](../architecture/characters.md)) will be built from, with licenses checked for **commercial use in a paid app** (data shipped inside app packages). The output decides what the pipeline can generate offline and what must be authored (by AI + human review). Research only: no code.

## Read only
- `docs/architecture/characters.md` (whole file, 30 lines).
- Nothing else in the repo.

## Do
For each data need below, find 1–3 candidate sources. For each candidate record: URL, license (exact name + version, link to the license text), commercial use OK?, obligations (attribution, share-alike, copyleft scope — does it reach our app code or only the data file?), coverage (simplified chars, ≥ HSK 1–6 / ~3000 chars), format, last update, and quality on the samples **妈 学 谢 你 们 喝**.

1. **Hán-Việt readings** for simplified characters (e.g. Unihan `kVietnamese` is keyed by traditional chars — how to map simplified → traditional, e.g. 学→學, 谢→謝; coverage gaps).
2. **Decomposition / IDS** into components, ideally with semantic vs phonetic role (e.g. cjkvi-ids, CHISE, Make Me a Hanzi `dictionary.txt` `etymology` field, Wiktionary). Does the source decompose 学/谢 sensibly for simplified forms?
3. **Stroke-order paths** for an animation (Make Me a Hanzi / Hanzi Writer data, AnimCJK). Note the Arphic Public License obligations precisely.
4. **Frequency + level lists:** HSK 3.0 (2021) character/word lists, a frequency list (e.g. SUBTLEX-CH, Jun Da). Licenses of the lists themselves.
5. **Meanings:** English (CC-CEDICT) and any **Vietnamese** source (Vietnamese Hán-Việt dictionaries, Thiều Chửu, Wiktionary vi). If none is usable, say so — the fallback is AI-generated Vietnamese meanings with human review.
6. **Component names in Vietnamese** (bộ thủ names like 氵 "ba chấm thủy", 讠 "ngôn đứng") — a usable list for the ~214 radicals + common simplified components.

Then write `docs/research/characters_data.md` (≤ 150 lines):
- One table per need: candidates × the fields above.
- A **recommendation** per need (one source, or "author it"), and the combined attribution/NOTICE text the app would have to show.
- A sample block: the full proposed record for 妈 and 谢 assembled from the recommended sources (reading, components + roles, Hán-Việt, pinyin, meanings, stroke data available y/n).
- Risks: anything copyleft that could reach `kmp/` code, gaps that need authoring, how big the bundled data would be.

## Acceptance
- Every recommended source has a verified license link (read the license file in the source repo, not a blog summary). Unclear license → marked "not used".
- 妈 and 谢 sample records are complete or each gap is named.
- Doc ≤ 150 lines, English.
