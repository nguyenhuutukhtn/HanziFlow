# X5 — Explain: per-provider cooldown after 429 (skip a locked provider until its window resets)
Status: todo · Suggested agent: Claude Sonnet subagent (medium) · Session: new · Size: S–M · Device check: user
Wave: 7 · Owns: `kmp/android/src/main/kotlin/com/hanziflow/ai/`, `kmp/android/src/main/kotlin/com/hanziflow/di/AiModule.kt`, `kmp/android/src/main/kotlin/com/hanziflow/ui/explain/ExplainSheet.kt` + `res/values/strings.xml` (quota message only), tests under `kmp/android/src/test/kotlin/com/hanziflow/ai/` · Depends on: X4 + the uncommitted PM edit in `ai/ChatClient.kt` / `FallbackChatClientTest.kt` (fall back on **any** failure — keep it) · Checkpoint after: yes

## Goal
User, 2026-10-25: after a provider returns 429, the next requests go straight to the next provider until
that provider's limit window resets — no wasted round trip to a provider that is known to be locked.
The window length comes from the provider's answer (per minute vs per day), not a fixed guess.

## Read only
`ai/ChatClient.kt` (`FallbackChatClient`, `ChatFailure`), `ai/OpenAiCompatibleClient.kt` (where HTTP errors become `ChatFailure`), `di/AiModule.kt`, `ExplainSheet.kt` error row.

## Do
1. **Capture the window on 429** in `OpenAiCompatibleClient`: add `retryAfterMs: Long?` and `window: QuotaWindow (MINUTE | DAY | UNKNOWN)` to `ChatFailure`. Sources, first match wins:
   - HTTP header `Retry-After` (seconds) — Groq/DeepSeek/OpenRouter style.
   - Gemini body (its OpenAI-compatible endpoint may wrap the error in a JSON **array** `[{"error":{…}}]` or return a plain object `{"error":{…}}` — accept both): `error.details[]` entries with `@type` ending `google.rpc.RetryInfo` → `retryDelay` like `"34s"` / `"1.5s"`; entries ending `google.rpc.QuotaFailure` → `violations[].quotaId`; quotaId containing `PerDay` → `DAY`, `PerMinute` → `MINUTE`.
   - Parsing must never throw; anything unparseable → `UNKNOWN`, no retryAfter.
2. **Cooldown rule** (`ProviderCooldowns`, keyed by `model + base_url`): `DAY` → until the next midnight America/Los_Angeles (Gemini's daily reset); `MINUTE` → max(retryAfter, 60 s); `UNKNOWN` with retryAfter → retryAfter; `UNKNOWN` without → 60 s, doubled on each consecutive 429 of that provider, capped at 30 min, reset on its next success. Inject a `Clock` (`() -> Long`) for tests.
3. **Persist** cooldowns in `SharedPreferences` (`ai_cooldowns`), so a daily lock survives an app restart; expired entries are ignored/removed on read.
4. **FallbackChatClient** skips providers whose cooldown is active; on success clears that provider's backoff. If **every** provider is cooling down, do not call anything: throw `ChatFailure(429, quotaExhausted = true)` carrying the earliest reset time. Non-429 failures still fall back (PM edit) but set no cooldown.
5. **Sheet:** the quota message adds the earliest reset as local time when known: "Hết lượt miễn phí của AI. Thử lại sau 14:05." (existing text otherwise).
