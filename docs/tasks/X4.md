# X4 — Explain: provider fallback chain, friendly quota errors, reuse explanations of identical lines
Status: todo · Suggested agent: Claude Sonnet subagent (medium) · Session: new · Size: S–M · Device check: user
Wave: 7 · Owns: `kmp/android/src/main/kotlin/com/hanziflow/ai/`, `kmp/android/src/main/kotlin/com/hanziflow/di/AiModule.kt`, `kmp/android/build.gradle.kts` (llm config only), `kmp/android/src/main/kotlin/com/hanziflow/ui/explain/ExplainSheet.kt`, `kmp/android/src/main/res/values/strings.xml`, `kmp/android/src/main/kotlin/com/hanziflow/data/CourseDatabase.kt` (DAO query only, no schema change), tests under `kmp/android/src/test/kotlin/com/hanziflow/ai/` and `.../ui/explain/` · Depends on: X2, X3 (committed) · Checkpoint after: yes

## Goal
Free tiers return HTTP 429 after a few long answers (device check 2026-10-25: Gemini `gemini-3-flash-preview`).
The app tries an ordered list of providers instead of one, tells the learner plainly when all are out of
quota, and does not pay twice for the same sentence that appears in several modes (lesson 1: 653 Chinese
lines, only 114 distinct texts).

## Read only
`docs/tasks/WAVE-7.md`, the `ai/` package and `di/AiModule.kt`, `kmp/android/build.gradle.kts` (the `llmProp` block), `ExplainSheet.kt` (assistant message rendering + error row), `CourseDatabase.kt` (explain DAO).

## Do
1. **Config, backward compatible:** keep `llm.base_url` / `llm.model` / `llm.api_key` as provider 1. Add optional providers 2..4 as `llm.2.base_url`, `llm.2.model`, `llm.2.api_key` (same for 3, 4). A provider whose `api_key` is blank but `base_url` is blank too inherits nothing and is skipped; a provider with only `llm.N.model` set (base_url and key blank) **reuses provider 1's base_url and key** (Gemini Flash → Flash-Lite with the same key). Emit them to BuildConfig as one JSON string field `LLM_PROVIDERS` (array of `{base_url, model, api_key}`), parsed into `List<AiConfig>`; `isConfigured` = at least one complete provider.
2. **`FallbackChatClient(clients)`:** tries in order; moves to the next on HTTP 429, 5xx, timeout or IOException; does **not** fall back on 400/401/403/404 (config errors: report them). Returns the answer plus which model answered. When every provider failed with 429, throw `ChatFailure(429, …)` flagged `quotaExhausted = true`.
3. **Record the model:** `ChatMessage` gets an optional `model: String? = null` (serialized; old rows without it still parse). Assistant messages store it; the sheet shows it under each answer in small `onSurfaceVariant` text (e.g. `gemini-3-flash-preview`).
4. **Friendly errors** in the sheet's error row (strings.xml, Vietnamese): quota → "Hết lượt miễn phí của AI. Thử lại sau ít phút hoặc thêm nhà cung cấp khác."; timeout/network → "Không kết nối được AI. Kiểm tra mạng rồi thử lại."; other → "AI báo lỗi (<code>)." Never show raw response bodies.
5. **Reuse identical lines:** in `explain(target)` when there is no thread for (lessonId, lineId), look for a thread in the same lesson with the **same hanzi** (any lineId, not stale); if found, save a copy under this lineId (explanation messages only — the first user + first assistant message, not that line's follow-ups) and return it with **no network call**. Add the DAO query needed (by lessonId + hanzi); no schema/version change.

- `ExplainRepositoryTest`: line B with the same hanzi as already-explained line A → **0 calls**, B's thread has 2 messages, A's follow-ups not copied; different hanzi → 1 call.
- Old stored thread JSON without `model` still loads.
- Sheet test: quota failure shows the quota text; an answer shows its model label.
- `scripts/check.sh` passes (the web follow-check flake: re-run once, then report it as the known flake).
