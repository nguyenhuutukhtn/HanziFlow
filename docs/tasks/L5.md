# L5 — "Jump to current line" button in the transcript
Status: todo · Suggested agent: Codex IDE extension, gpt-5.6-luna (low) · Session: new · Size: S/M · Device check: user

## Why
`TranscriptPanel.kt` already auto-scrolls to the active line, but only resumes
5s after the user stops dragging (`AUTO_SCROLL_PAUSE_MS`) — if they're still
reading when it fires, it snaps away under them, and there is no way to jump
back on demand. User report (2026-10-21): scrolling up/down to read ahead or
back, no button to return to the highlighted line.

## Read only
`AGENTS.md`, this brief, `.claude/skills/android-ui-testing/SKILL.md`,
`kmp/android/src/main/kotlin/com/hanziflow/ui/player/{TranscriptPanel.kt,NowPlayingScreen.kt}`,
`kmp/android/src/test/kotlin/com/hanziflow/ui/PlayerUiTest.kt`.

## Do
1. Track whether the active line (`activeLineIds`) is currently within
   `listState.layoutInfo.visibleItemsInfo` (derived state, not a per-frame
   recompute). When it is false — whether because the user scrolled away or
   because the active line changed off-screen — show a small floating
   affordance over the transcript (e.g. a pill/FAB near the bottom, "↓ Dòng
   đang nghe" or a down-chevron icon with that content description).
2. Tapping it calls `listState.animateScrollToItem(index)` immediately and
   clears `scrollPausedUntil`, instead of waiting for the existing 5s timer.
   Keep the existing auto-resume-after-5s behavior as is — this button is an
   additional, immediate way back, not a replacement.
3. Hide the button once the active line is back in view (don't rely only on
   the tap — the user may also scroll back manually).
4. **Both touched files are at/over the 300-line budget** (`TranscriptPanel.kt`
   337 ⚠, `NowPlayingScreen.kt` 300). Extract the new scroll-visibility
   tracking + button composable into a new file under `ui/player/` rather than
   growing either; do not let `TranscriptPanel.kt` grow past 337.
5. Compose UI test (JVM, `PlayerUiTest` style): with a tall line list and a
   position far from the active line, assert the button exists; tapping it
   then asserts the active line's row is in the semantics tree near the top
   (or assert via a test-tag on the active row + `onNodeWithTag` after the
   click, whichever is cheaper to make deterministic under Roborazzi/JVM —
   LazyColumn scroll completion in tests may need `compose.waitForIdle()`).
6. Update `docs/STATUS.md` (L5 done) and add a `docs/token_log.md` row. Do not commit.
