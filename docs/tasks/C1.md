# C1 — Pipeline: characters.json per lesson package
Status: todo · Suggested agent: fresh Codex or DeepSeek · Size: M · Device check: user (none)

## Goal
`mandarin-course publish` adds `characters.json` to each lesson package. The file lists the new characters introduced in the lesson and the components the learner needs to know first (not yet seen in prior lessons), assembled from offline data sources (Unihan, MMAH, hsk30, CC-CEDICT). No AI calls at publish time. `vi_meaning` is always null; stroke animation is flagged by availability only.

## Prerequisites
- C0 done: `data/radicals_vi.json` exists.
- Data files present (not committed, fetched once by the agent):
  - `data/mmah/dictionary.txt` (Make Me a Hanzi JSONL, ~9000 chars).
  - `data/hsk30/` (ivankra/hsk30 CSV).
  - `data/cedict/cedict_ts.u8` (CC-CEDICT UTF-8 text).
  - `data/unihan/Unihan_Readings.txt` (Unicode UCD TSV, fields kVietnamese + kTraditionalVariant).
  - `data/hanzi_writer/` (Hanzi Writer data JSON files — used only to populate `stroke_available`).

## Do

### 1. Data loader (`src/mandarin_course/characters/data.py`)
- Load and cache (module-level dict) each source at first call:
  - `MmahLoader`: parse MMAH JSONL → `{char: {decomp_ids, semantic, phonetic, hint, etymology_type}}`.
  - `UnihanLoader`: parse `Unihan_Readings.txt` → `{char: {han_viet, traditional_variant}}`. For simplified chars, first try direct kVietnamese; fallback to `kTraditionalVariant` → look up that codepoint's kVietnamese.
  - `Hsk30Loader`: parse CSV → `{char: hsk_level}`.
  - `CedictLoader`: parse CC-CEDICT → `{char: en_meaning}` (first single-char entry's English gloss, stripped of brackets/numbers).
  - `StrokeLoader`: list Hanzi Writer JSON filenames → set of chars with stroke data.
  - `RadicalsLoader`: load `data/radicals_vi.json` → `{char: {name_en, name_vi}}`.
- Each loader silently skips missing data files and returns an empty dict; publish will warn but not fail.

### 2. Character resolver (`src/mandarin_course/characters/resolve.py`)
- `resolve_char(char, loaders) -> dict`: build one character record per schema.
- `resolve_lesson_characters(lesson_json, seen_chars: set, loaders) -> dict`: 
  - Extract chars from lesson words (tokenize lesson segments using a simple CJK codepoint scan — no NLP library).
  - For each new char (not in `seen_chars`): resolve it.
  - For each component (`semantic`, `phonetic`) of new chars: if not in `seen_chars` and not in the new chars, add it to `components_prereq`.
  - Return the `characters.json` dict.
  - Update `seen_chars` in place.

### 3. Hook into publish (`src/mandarin_course/publish.py`)
- After existing package artifacts are written, call `resolve_lesson_characters` and write `characters.json` to the temp package dir.
- Pass a per-lesson-run `seen_chars` set (empty for now — cross-lesson tracking is out of scope for C1; add it in a follow-up).
- Include `characters.json` in the digest comparison (unchanged check) and in `items.json`-style manifest if one exists.

### 4. Tests (`tests/test_characters.py`)
- Unit-test `resolve_char` with a small inline fixture (no real data files needed; mock loaders).
- Integration-test `resolve_lesson_characters` against lesson_001 JSON (read from `lessons/lesson_001.json`): assert `characters` is a non-empty list, every entry has required fields, `vi_meaning` is always null.

### 5. Update contract fixtures
- Re-run `just lesson 001` dry-run (0 paid TTS) and publish to update `kmp/shared/src/commonTest/resources/contract/` if `characters.json` is a new file in the package.

## Acceptance
- `just check` passes (pytest incl. `test_characters.py`, shared + android unit tests, codemap, file-size).
- `just lesson 001` (dry-run + publish) produces `publish/lesson_001/vN/characters.json` with ≥1 character entry.
- Every entry has: `char`, `pinyin` (from CC-CEDICT or blank), `han_viet`, `hsk_level`, `decomp_ids`, `semantic`, `phonetic`, `en_meaning`, `vi_meaning: null`, `stroke_available`, `lesson_words`.
- No new source file over 300 lines (codemap audit passes).
- `publish` exits with an error and a clear message if a data file is present but malformed.
