# X1 — Explain prompt + provider comparison script
Status: todo · Suggested agent: Claude Haiku subagent (low) · Session: new · Size: S · Device check: user (read the comparison file)
Wave: 7 · Owns: `prompts/explain_line.md`, `scripts/llm_compare.py`, `tests/test_llm_compare.py` · Depends on: none · Checkpoint after: no

## Goal
One prompt file that both the Android app (X2) and a comparison script use, and a script that sends
the same 5 lesson-2 lines to every configured provider and writes the answers side by side, so the
user picks a provider by reading, not guessing.

## Read only
`docs/tasks/WAVE-7.md`, `publish/lessons/lesson_002/v4/reference.json` (query it with a short script, don't read it whole; Chinese text of a line lives there, keyed by line id).

## Do
1. `prompts/explain_line.md`: the system prompt + a user template with placeholders `{{hanzi}}`, `{{pinyin}}`, `{{meaning_vi}}`, `{{context_before}}`, `{{context_after}}`. Ask for, in Vietnamese, for a beginner learning by ear: pinyin, natural Vietnamese translation, each chunk (hanzi · pinyin · meaning, characters broken down), grammar points and word usage, a short "dễ nhầm" note if any. Markdown, headings + bullet lists, no tables wider than 3 columns, no "review whether the script is natural" section (this is for the learner, not a content reviewer). Keep it under ~40 lines. Follow-up turns need no template (plain chat history).
2. `scripts/llm_compare.py` (stdlib only: `urllib`, `json`): providers from env, each enabled only if its key is set — `GEMINI_API_KEY` (base `https://generativelanguage.googleapis.com/v1beta/openai/`), `GROQ_API_KEY` (base `https://api.groq.com/openai/v1/`), `DEEPSEEK_API_KEY` (base `https://api.deepseek.com/v1/`); model per provider from `GEMINI_MODEL` / `GROQ_MODEL` / `DEEPSEEK_MODEL` (no hard-coded default for Gemini/Groq: if missing, print `set <NAME>_MODEL; see --list-models`). Load `.env` itself (simple `KEY=VALUE` parse). POST `<base>chat/completions`.
   - `--list-models <provider>`: GET `<base>models`, print ids only.
   - `--dry-run`: print the 5 lines and the rendered user prompt of the first, call nothing.
   - default: for each line × provider, write `docs/reviews/llm_compare.md` (line, then `### <provider> · <model> · <seconds>s` + answer). One provider failing (HTTP error, timeout 60 s) writes the error under its heading and continues.
   - 5 lines: pick from lesson 2 v4 by text, include `大厅在楼里面，很大。` if present (else the line containing `大厅`), plus 4 others of different length/grammar; context = 2 lines before/after in the same track.
   - Never print or write a key (not in errors either: redact the `Authorization` header from any exception text).
3. `tests/test_llm_compare.py`: prompt rendering fills every placeholder (no `{{` left); `.env` parse; a provider with no key is skipped; one provider raising an HTTP error still lets the next run (monkeypatch the HTTP function); output file contains each provider heading; the key string never appears in output or logged errors.

## Acceptance
- `--dry-run` prints 5 lines including one containing `大厅`, exits 0, makes no network call.
- Tests pass; `scripts/check.sh` passes.
